# MKS Series 275 RS-485 protocol handoff

## Scope and provenance

The checkout contained no source, manuals, or device-specific notes at the time of research. The protocol below is extracted from the official MKS **Series 275 Mini-Convectron Module with RS-485 and Dual Process Relays** instruction manual, document **275547, Revision C, December 2021**, especially §§2.3, 3.8, 4.3–4.4.6 (printed pages 17, 27, 29–38):

- Official PDF: <https://api.p1.mks.com/mam/celum/celum_assets/resources/GP-275Module-275547-MAN.pdf?1=>
- The manual says it applies to the RS-485 + dual-process-relay Mini-Convectron variant; verify the actual module/catalog number before enabling writes. It is not evidence that every product sold as “MKS 275” uses this protocol.

## Serial and bus assumptions

- Physical layer: two-wire RS-485. The manual allows up to 32 devices and a maximum total cable length of 4,000 ft. On an idle bus every node listens; the host should provide the required RS-485 bias resistors (manual §3.8, printed p. 27).
- Factory serial defaults: **19,200 baud, ASCII 8 data bits, no parity, 1 stop bit (8N1)**; default address `01` (§4.3, p. 29).
- Supported baud rates: 300, 600, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200. Supported formats are 8N1, 7O1, and 7E1 (§2.3, p. 17).
- No checksum/CRC field is specified anywhere in the RS-485 framing or command set. Do not add one.

## Frame syntax

Host command:

```text
# <2 ASCII address digits> <command/data> <CR>
```

The literal spaces shown above are notation, not a blanket rule. In the manual, `_` denotes a literal space and `<CR>` is byte `0x0D`; commands have variable lengths. For example, the documented pressure read is `#01RD <CR>` (bytes `23 30 31 52 44 20 0D`). Some commands such as `RH+`/`RL-` are shown without the extra space (`#01RH+<CR>`), so command templates should follow the individual examples.

- Start character is `#` (`0x23`).
- Address is two ASCII digits representing the module’s hexadecimal address; `0F` means address 15. The front-panel address selector is 0–15 (`00`–`0F`). The programmed `SA` offset is added to that selector.
- Alphabetic command input may be upper- or lower-case; responses are uppercase.
- Successful responses start with `*`, carry the addressed data/status, and terminate with `CR`. Syntax/unknown-command errors start with `?`, e.g. `?01_SYNTX_ER<CR>`.
- Parse to `CR` and validate the response prefix/address rather than assuming every response has the same payload width; the manual says data fields are 13 characters but its command examples vary.

## Commands required for an implementation

Examples use address `01`; replace it with the active address.

| Command | Direction / payload | Documented behavior and response |
|---|---|---|
| `RD` | Read pressure | `#01RD <CR>` → `*01_9.34E-02 <CR>` (scientific notation). Three significant digits normally; low ranges use filler zeros. Vacuum can read `-0.00E-00`. `?01_DEF_SNSR` can mean defective transducer, pressure >999 Torr, or non-N2/air gas. |
| `SA` | Write offset, e.g. `SA20` | `*01_PROGM_OK`. Effective address changes only after power cycle or `RST`; selector value is added to offset. |
| `TS` | Write span in scientific notation | `*01_PROGM_OK` or calibration errors `*01_HI_ATM_V`, `*01_LO_ATM_V`, `?01_GAIN_LIM`, `?01_DEF_SNSR`, `?01_RANGE_ER`. Manual says TS must be above 399 Torr. |
| `TZ` | Write zero as scientific notation or `0` | `*01_PROGM_OK` or `*01_HI_VAC_V`, `*01_LO_VAC_V`, `?01_OFST_LIM`, `?01_DEF_SNSR`, `?01_RANGE_ER`. Manual says TZ must be below 0.1 Torr. |
| `SH` / `SL` | Write setpoint 2 / 1 with signed scientific value | `+` sets relay ON point and `-` sets OFF point; `*01_PROGM_OK`. Minimum hysteresis is 10 mV bridge voltage (about 10 Torr at atmosphere and 1 mTorr near vacuum). Automatic correction reports `+MIN HYS` or `-MIN HYS`; this controls relay direction. |
| `RH+` / `RH-`; `RL+` / `RL-` | Read setpoint 2 / 1 ON or OFF point | ON value begins with a space; OFF value begins with `-`. E.g. `#01RH+<CR>` → `*01_9.80E-02 <CR>`. |
| `VER` | Read firmware | `#01VER <CR>` → `*01_12997-00` (example: internal part number and revision). |
| `FAC` | Write factory defaults | `*01_PROGM_OK`; restores base address 01, zero/span defaults, 60 Hz A/D sample rate, 19200 baud, 8N1. Cycle power or send `RST` afterward. |
| `SB` | Write baud, e.g. `SB2400` | `*01_PROGM_OK`; old baud remains active until power cycle or `RST`; invalid value yields a range error; maximum is 115200. |
| `SPN` / `SPO` / `SPE` | Write serial format | `SPN` = 8N1, `SPO` = 7O1, `SPE` = 7E1; `*01_PROGM_OK`; new format takes effect after power cycle or `RST`. The manual’s SPO example appears to contain a typo (`#01SPE` is printed under both SPO and SPE); use the command names in the summary table. |
| `RST` | Reset module | No response. Behaves as power cycle; communication is re-enabled after approximately 2 seconds. |
| `SU` | Write units; final character `M`, `P`, or `T` | `M` = mbar, `P` = pascal, `T` = Torr; `*01_PROGM_OK`. Example: `#01SUT <CR>`. |
| `RU` | Read units | `*01 MBAR`, `*01 PASCAL`, or `*01 TORR`. |
| `SS` | Write sample averaging count, `SS01`–`SS08` | `*01_PROGM_OK`; allowed values are 1–8 samples. |
| `RSA` | Read averaging count | Example: `#01RSA <CR>` → `*AVG: 04` (response is not shown with the normal address form). |
| `SF` / `RF` | Write/read filament material | `SF G`/`SF P` (manual examples use `#01SFP`): `G` = gold, `P` = platinum; write returns program confirmation. `RF` returns e.g. `*01 GOLD`. SF is factory/service-oriented. |
| `PCS` | Read process-relay status | The two characters immediately before `PCS` encode relay state: LSB = relay 1, MSB = relay 2; `1` means energized/active. The PDF text extraction drops these two characters in its example, so parse by the command/status marker rather than relying on that malformed rendering. |

## Timing and errors

- The module turns its RS-485 driver off **80 µs after finishing its response** (§4.4.4). A host half-duplex implementation must leave RX enabled through the terminating CR and allow this turnaround before transmitting again.
- The manual’s approximate receive-to-response timing is a baud-dependent `T` plus command processing: `T` = 3.3 ms at 115200/57600/38400, 3.9 ms at 19200, 5.1 ms at 9600, 7.5 ms at 4800, 13 ms at 2400, 22 ms at 1200, and 79 ms at 300. Add **105 ms for FAC**, **0 ms for RD**, **17 ms for all other responding commands**; `RST` has no response (§4.4.6, p. 38).
- Out-of-range input voltage replaces the desired response with `*HI VOLTAGE` or `*LO VOLTAGE` (§4.4.5).
- A transaction should be serialized per bus: one request, collect through CR or timeout, classify `*`/`?`, then permit the next request. There is no unsolicited/streaming response described by this manual.

## Safety/implementation caveats

- `TS`, `TZ`, `SH`, `SL`, `FAC`, `SB`, `SPN`, `SPO`, `SPE`, `RST`, `SU`, `SS`, and `SF` are writes or state-changing operations. UI/active-master code should mark these as explicit writes and require confirmation where appropriate.
- MKS warns that indicated pressure depends on gas and orientation; RD values for gases other than N2/air are not direct true-pressure values. `?01_DEF_SNSR` can be caused by helium at atmosphere, not only a hardware fault.
- The exact hardware variant and firmware should be confirmed before relying on command availability, relay semantics, or calibration behavior.
